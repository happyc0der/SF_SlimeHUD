# SF_SlimeHUD 2.0.6

- Made SlimeHUD **opt-in by default**: `waila.default-enabled: false` leaves a new/unspecified player's HUD off until they run `/slimehud toggle`.
- Player opt-in and opt-out choices are saved to the existing `player.yml` and survive restarts; saved explicit `waila: true` is honored without resetting player data.
- Opted-out players have no active native controller, BossBar, or repeating HUD task. Status and PlaceholderAPI now use the same preference default and report the opt-out state accurately.
- Keep `waila.disabled: false` so players are permitted to toggle the HUD on.

- Added optional `waila.crouch-only: true` to show the HUD while Shift is held, hide immediately on release, and default to the original always-on mode.
- Removed the What Is That? (WIT) bridge, restoring native-only BossBar/ActionBar control.
- Invalidated delayed region/item inspection results after the player stops crouching and restarted scanning on the correct player scheduler.
- Preserved Slimefun machine progress, energy, generators, cargo/network information, vanilla block/item targeting, per-player preferences and JustEnoughGuide overrides.
- Improved `/slimehud status` when `waila.disabled: true` deliberately prevents controller creation.
- Retained Java 21 bytecode and Minecraft 1.21.11+ compatibility. Experimental Folia 26.3 support remains gated.

Existing configurations with `waila.disabled: true` must be changed to `false`; add `default-enabled: false` to default new players to off and `crouch-only: true` for Shift-only HUD.

Release requires source-matched CI/runtime verification and a rebuilt canonical Slimefun Legacy addons ZIP.
