# SF_SlimeHUD 2.0.5

Native HUD targeting now keeps both block rays and the expanded dropped-item search area inside the current region's owned chunks. This fixes Folia errors when a long configured range or an integration's per-player distance override crosses a region boundary. Nearby blocks and dropped items remain visible, and a fully owned ray keeps its exact requested distance.

The minimum API remains Paper 1.21.11 with Java 21 bytecode. The compatibility workflow adds Paper/Purpur 26.3 and experimental Folia 26.3 runtime checks, including a real native ownership regression, a pinned released-code negative control, and a clean restart with unchanged existing player settings.

The native regression fixture uses synthetic player accessors backed by a real server entity and the unmodified production HUD updater. It does not establish connected-client rendering or every Slimefun/addon HUD handler. Folia 26.3 remains an experimental target while upstream builds are ALPHA.

Player settings, commands, placeholders, handlers, item identities, and the optional WIT/JEG integration APIs retain their existing formats and behavior. Publication requires an explicit manual dispatch after the candidate's build and runtime gates pass; existing tags and assets are preserved.
