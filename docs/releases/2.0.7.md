# SF_SlimeHUD 2.0.7 — First-run defaults and player toggle diagnostics

- Correct new-install `config.yml` to default to `waila.disabled: false`, `waila.default-enabled: false`, `waila.crouch-only: true`. Players start off, may opt in using `/slimehud toggle`, and then see native HUD information only while holding Shift.
- Preserve existing administrator configurations and every player's saved `player.yml` choice (including previous enabled/disabled values); do not silently reset them.
- Clarify when `waila.disabled: true` blocks all player toggles; the error describes the exact setting and how to reload it.
- Expand `/slimehud status` to show the installed plugin version, global-disable and default-enabled flags, plus whether each player's preference comes from saved data or the server default.
- Log the actual SlimeHUD configuration path and effective settings on startup to diagnose old JARs, duplicate installs and stale configuration.
- Add regressions for packaged defaults, two consecutive toggle actions, global-disable behavior and the persistence-store preference identifier.
- Preserve Minecraft 1.21.11+ support, Java 21 bytecode, native Slimefun Legacy machine/energy/cargo/vanilla/dropped-item HUD, and region-safe scheduling. Folia 26.3 remains experimental.

The old `waila.disabled: true` value globally disables the plugin's HUD and is **not** the player-default-off setting. To permit opt-in, set `disabled: false` and `default-enabled: false`. An existing configuration may need its own `crouch-only: true` because saved files are intentionally not overwritten.
